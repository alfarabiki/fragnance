# ATLASE — SEO Strategy

## 1. Routes

All public-facing, SEO-optimized routes:

| Route | Purpose | Dynamic? |
|-------|---------|----------|
| `/` | Homepage — brand intro, featured aromas, CTA | Static (ISR) |
| `/aroma/:slug` | Product detail page (e.g., `/aroma/dior-inspired`) | Static (ISR, `generateStaticParams`) |
| `/parfum/50ml` | Category: 50ml parfum catalog | Static (ISR) |
| `/parfum/30ml` | Category: 30ml parfum catalog | Static (ISR) |
| `/parfum/100ml` | Category: 100ml parfum catalog | Static (ISR) |
| `/buat-parfum` | Customization builder landing | Static |
| `/faq` | Frequently asked questions | Static (ISR) |
| `/tentang` | About ATLASE | Static |
| `/kebijakan-privasi` | Privacy policy | Static |
| `/syarat-ketentuan` | Terms & conditions | Static |
| `/404` | Not found page | Static |

**Route naming convention:**

- Indonesian-language slugs for brand consistency (`buat-parfum`, `tentang`, `syarat-ketentuan`).
- Product slugs are derived from the product name in lowercase-kebab-case (e.g., `dior-inspired`, `bleu-de-chanel-type`).
- Category routes use the pattern `/parfum/{size}ml`.

## 2. Metadata Model Per Product

Every `/aroma/:slug` page renders the following metadata via Next.js `generateMetadata`:

```ts
// app/aroma/[slug]/page.tsx (server component)
import type { Metadata } from 'next'

export async function generateMetadata({ params }): Promise<Metadata> {
  const product = await getProduct(params.slug)

  return {
    title: `${product.name} — Parfum Custom Premium | ATLASE`,
    description: product.seoDescription,        // max 160 chars
    alternates: {
      canonical: `https://atlase.id/aroma/${product.slug}`,
    },
    openGraph: {
      title: `${product.name} — ATLASE`,
      description: product.seoDescription,
      url: `https://atlase.id/aroma/${product.slug}`,
      siteName: 'ATLASE',
      images: [
        {
          url: product.ogImageUrl,               // 1200×630, AVIF/WebP
          width: 1200,
          height: 630,
          alt: product.name,
        },
      ],
      locale: 'id_ID',
      type: 'website',
    },
    twitter: {
      card: 'summary_large_image',
      title: `${product.name} — ATLASE`,
      description: product.seoDescription,
      images: [product.ogImageUrl],
    },
  }
}
```

### Structured Data (JSON-LD)

Injected inside the page component via `<script type="application/ld+json">`:

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Dior Sauvage Inspired — ATLASE",
  "description": "Parfum custom dengan aroma Dior Sauvage, buatan tangan di Indonesia.",
  "image": "https://atlase.id/images/aroma/dior-inspired.avif",
  "brand": {
    "@type": "Brand",
    "name": "ATLASE"
  },
  "offers": {
    "@type": "Offer",
    "url": "https://atlase.id/aroma/dior-inspired",
    "priceCurrency": "IDR",
    "price": "149000",
    "availability": "https://schema.org/InStock",
    "seller": {
      "@type": "Organization",
      "name": "ATLASE"
    }
  }
}
```

**Rules:**

- `price` is in IDR integer format (no decimals for IDR).
- `url` in structured data **must** match the canonical URL exactly.
- `image` must be the OG image URL (absolute, same-origin).
- Revalidate structured data with ISR alongside page revalidation.

## 3. OG Images

| Property | Value |
|----------|-------|
| Dimensions | 1200 × 630 px |
| Format | AVIF primary, WebP fallback (served via `<picture>` or Next.js `Image`) |
| Hosting | Cloudflare CDN (`/og/{slug}.avif`) |
| Generation | Static OG images generated at build time from product data + template |
| Alt text | Product name + "ATLASE" |

**Template composition:**

- Background: product fragrance color gradient (from product metadata).
- Product visual: transparent PNG/WebP cutout centered.
- Text overlay: product name (top-left), price in IDR (bottom-right), ATLASE logo (bottom-left).
- Font: brand display font (subset Latin + Basic Indonesian).

**Fallback:** If a product is missing an OG image, the default `og-default.avif` is used (ATLASE brand lockup).

## 4. Sitemap + Robots

### sitemap.xml

```xml
<!-- Generated by Next.js Metadata API: app/sitemap.ts -->
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://atlase.id/</loc>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://atlase.id/aroma/dior-inspired</loc>
    <changefreq>weekly</changefreq>
    <priority>0.9</priority>
  </url>
  <!-- ... one <url> per /aroma/:slug, /parfum/:size, /faq, /tentang -->
</urlset>
```

- Generated via `app/sitemap.ts` using `MetadataRoute.Sitemap`.
- ISR revalidation: **daily** (products may change price/status frequently).
- Excludes: `/checkout/*`, `/api/*`, `/404`, any route with `noindex` in metadata.

### robots.txt

```txt
User-agent: *
Allow: /
Disallow: /api/
Disallow: /checkout/
Disallow: /admin/

Sitemap: https://atlase.id/sitemap.xml
```

## 5. Internationalization

| Aspect | Value |
|--------|-------|
| Primary locale | `id-ID` (Indonesian) |
| HTML `lang` attribute | `<html lang="id">` |
| Content language | Indonesian (Bahasa Indonesia) |
| Hreflang | Not implemented (single locale for now) |
| Currency | IDR throughout (structured data, UI, analytics) |
| Future: `en` locale | If added, routes become `/en/aroma/:slug` with `hreflang` pairs |

**Metadata locale:** All `openGraph.locale` values use `id_ID`.

## 6. Performance-for-SEO Notes

SEO ranking is directly impacted by Core Web Vitals. The performance targets in `performance.md` are SEO-critical:

- **LCP < 2.5s** on mid-range Android/4G — ensures fast first meaningful paint for Google's mobile crawler.
- **CLS < 0.1** — no layout shifts from images, fonts, or dynamic content.
- **INP < 200ms** — fast interaction response for mobile users.
- **TTFB < 800ms** — CDN + ISR ensures server response is fast.
- **Structured data** renders server-side (not client-hydrated) for guaranteed Googlebot parsing.
- **ISR** ensures product pages are pre-rendered, not SPA-dependent — Googlebot sees full HTML.
- **No client-side routing for SEO-critical pages** — all product/category pages are server-rendered on first load.

## 7. No-ID-in-URLs Rule

**Absolute rule:** Internal database UUIDs (`product_id`, `order_id`, etc.) must **never** appear in public-facing URLs.

| ✅ Good | ❌ Bad |
|---------|--------|
| `/aroma/dior-inspired` | `/aroma/a1b2c3d4-e5f6-7890-abcd-ef1234567890` |
| `/parfum/50ml` | `/parfum/42` |
| `/buat-parfum` | `/builder?product=123` |

**Implementation:**

- Product pages resolve via a `slug` column in the `products` table (unique, indexed).
- The `slug` is set once at product creation and is immutable.
- Internal API routes may use UUIDs, but the public `href` always references the slug.
- Redirects: if a slug ever changes (rare), a 301 redirect from old slug → new slug is added to `redirects.json` or handled in middleware.
